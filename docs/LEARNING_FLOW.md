# 学習の順序

[README.md](../README.md) へ戻る

この文書は、SCAO Learningで「どの順番で学習・制作するのか」を説明します。SCAOが存在する理由は [SCAO_CONCEPT.md](SCAO_CONCEPT.md)、教材とRepositoryの案内は [LEARNING_RESOURCES.md](LEARNING_RESOURCES.md) を参照してください。

最初から詳細理論を覚える必要はありません。各Levelで「今やること」が分かれば十分です。

## Orientation：SCAOの考え方を知る

まず、次の4点だけを押さえてください。

- **なぜGoalが必要か**  
  実装に入ると作業が増え、何のための制作かが曖昧になりやすいためです。
- **なぜ完成条件が必要か**  
  「もう少し良くできる」は終わりにくいため、どこまで作れば完成かを先に決めるためです。
- **なぜAI環境を最初に準備するのか**  
  学習・調査・設計・実装支援・レビューで使う相手を、最初に揃えておくためです。
- **AIを何のために使うのか**  
  制作の代行者ではなく、自分が判断しながら進めるための支援者として使うためです。

詳細な背景は [SCAO_CONCEPT.md](SCAO_CONCEPT.md) にあります。Orientationでは、理論を暗記するのではなく、この4点を確認すれば十分です。

## Level 0：AI学習環境を準備する

基本4Gemは次のとおりです。Persona本文と設定手順の正本は [`ai-setup-materials`](https://github.com/t-oikawa-sendai/ai-setup-materials) です。

```text
Researcher（調査担当）
    ↓
Solution Partner（設計パートナー）
    ↓
Code Generator（コード生成担当）
    ↓
Reviewer（レビュー担当）
```

Level 0では、Persona設計の理論は詳しく扱いません。次が分かれば利用を開始できます。

| Gem | 何を依頼するか | いつ使うか |
|---|---|---|
| Researcher（調査担当） | 事実と根拠の調査 | 分からないことを調べたいとき |
| Solution Partner（設計パートナー） | 目的・要求・設計の整理 | 何をどう作るかを考えたいとき |
| Code Generator（コード生成担当） | コード生成・修正の支援 | 実装や修正の支援が必要なとき |
| Reviewer（レビュー担当） | 成果の点検 | 設計・コード・確認結果を見直したいとき |

### Level 0 完了条件

- 基本4Gemを設定できている
- 各Gemへ何を依頼するか大まかに分かる
- AIの回答を自動的に正解として扱わない
- 秘密情報・個人情報を不用意に入力しない

### ＋α：Researcher Deep Research（詳細調査用）

`Researcher Deep Research（詳細調査用）` は追加設定です。基本4Personaとは別Personaではありません。Researcher（調査担当）Personaを利用する追加Gemです。Level 0の必須設定にはしません。

## Level 1：目的・要求・完成条件を決める

実装の前に、次を自分の言葉で整理します。

- なぜ作るか
- 誰のために作るか
- 何を解決するか
- どの状態を完成とするか

ここが曖昧なまま作り始めると、機能追加が続き、完成地点が見えなくなります。

## Level 2：要件・簡易設計を考える

次を整理します。

- 必要な機能
- 作るもの
- 今回作らないもの
- システム構成
- 今回の完成範囲

規模によっては、開発を分割します。

```text
第1次開発
→ 現在の完成対象

第2次開発
→ 次段階で追加する機能・改善

将来開発
→ アイデアとして残すが現在は実装しない
```

重要なのは「機能を削ること」ではありません。**どこまでを現在の完成対象とするかを管理すること**です。第2次以降の案を捨てる必要はありません。いま実装しない、と決めることが完成条件を守ります。

## Level 3：AIを活用して実装・検証する

### AI生成コードの理解

**AIが生成したコードを理解することは必要である。**

次の状態は、完成のKPIにしません。

- 動いた
- エラーが消えた
- AIが問題ないと言った

利用するコードについて、可能な範囲で次を理解します。

- 何をしているか
- なぜ必要なのか
- どこを変更すると何が変わるか
- 問題発生時にどこを見るか

すべてを一度に完璧に理解する必要はありません。分からない部分はAIへ質問し、自分の理解を増やしていきます。

### Coding Agent / Agentic AI

SCAOの初心者向けポートフォリオ制作では、**Coding AgentやAgentic AIへ開発作業を大きく委任する開発手法は取り上げません。**

技術そのものを否定するのではありません。理由は、初心者が「完成したが、自分では何が行われたのか説明できない」状態になることを避けるためです。

多少手間がかかっても、次を推奨します。

- 自分の目でコードを見る
- 自分で実行する
- 自分で動作確認する
- 分からない部分をAIへ質問する
- できる限り自分の手で修正する

基本姿勢は次のとおりです。

**AIは自分の代わりに開発する存在ではなく、自分が開発するための支援者として利用する。**

## Level 4：AIの役割分担・レビューを理解する

利用経験を持ったあとで、次を分離している理由を学びます。

- Researcher（調査担当）
- Solution Partner（設計パートナー）
- Code Generator（コード生成担当）
- Reviewer（レビュー担当）

同じAIに「調べる・決める・作る・良いと言う」をまとめて任せるより、役割を分けた方が、迎合や見落としに気づきやすくなります。

Evidence（確認に必要な記録・資料）についても、ここで理解を深めます。会話の印象ではなく、調査根拠、採用した要求、実行結果、レビュー指摘など、追跡できる記録を残す、という考え方です。詳細な運用は [`ai-setup-materials`](https://github.com/t-oikawa-sendai/ai-setup-materials) を正本とします。

## 学習サイクル

学習と制作は、一方向に固定しません。

```text
AI環境を準備
 ↓
学ぶ
 ↓
考える
 ↓
作る
 ↓
理解する
 ↓
テスト
 ↓
レビュー
 ↓
完成判断
 ↓
不足・問題
 ↓
教材またはAI環境を見直す
```

不足や問題が出たら、前のLevelや教材、AI環境の設定に戻って構いません。戻ることは失敗ではなく、Goalと完成地点を守るための作業です。
